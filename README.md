# library99 · 작은 도서관의 5일

Blender로 만든 도서관에서 책을 정리하고 이용자를 응대하는 5일간의 코믹한 사서 게임입니다.

**웹 플레이: https://sellys122.github.io/library99/dist/**

다운로드하려면 Code → Download ZIP 후 `dist/play.html`을 Chrome/Edge에서 엽니다. WebGL2와 하드웨어 가속이 필요합니다. 로컬 개발은 `python serve.py`로 실행합니다.

## 이번 운영 흐름

- 개관 시 5–7명이 입장합니다. 이후 20–30초마다 한 명씩 방문하며 현장 이용자는 최대 18명입니다.
- 게시판 / 서가 / 사서 문의 / 검색대 / 무인 대출반납기의 다섯 활동을 각각 같은 확률로 선택합니다. 사용 중인 기기에서는 줄을 서고 앞 이용자가 떠나면 이용합니다. 줄이 꽉 차면 자리가 날 때까지 기다립니다.
- 활동 후 60%는 퇴실하고 40%는 다른 활동을 합니다. 불만 이용자는 퇴실합니다. 동시 문의 최대 4건, 동행·데스크 응대 중인 이용자는 한 명까지입니다.
- 게시판은 약 10초 읽습니다. 운영시간 09:00–18:00, 월요일 휴관, 행사별 날짜·접수방법·정원은 게시판에서 확인합니다.
- 서가 이용 중 55% 확률로 “저기요!” 책 문의가 생깁니다. 사서에게 다가온 뒤 30초가 시작됩니다. “제가 안내해드릴게요” 또는 “잠시만요”를 고르면 새로 30초를 드립니다. 기다리라고 한 뒤에는 안내만 선택할 수 있습니다.
- 질문은 KDC의 십 단위 항목에 맞는 자연스러운 표현입니다. 이용자를 해당 백 단위 서가에 데려가 세부 분류를 선택합니다. 예: 일본 추리소설 → 800 문학 → 830 일본문학.
- 안내 후 5초 동안 책을 찾아 피드백합니다. 오답은 “책이 없네...”입니다. 올바르게 안내해도 정리하지 않은 서가는 15% 확률로 “책이 제자리에 없네?”가 발생하여 게시판 민원으로 남습니다. 정리 실패 서가는 무조건 찾기에 실패합니다.
- 정리 실패 서가의 다른 이용자도 30초 동안 고민하다 “서가가 어질러져있네”라고 떠나며 게시판 민원을 남깁니다.

## 서가정리 미니게임

서가에서 E → `서가를 정리한다`. 기존 책 5권과 꽂을 책 1권이 보입니다. 새 책을 틈에 드래그하거나 틈을 클릭/탭하고 `확인`을 누릅니다.

비교 순서: **분류 숫자 → 앞 문자 가나다순 → 저자 숫자열의 소수 자릿수 비교 → 뒤 문자 가나다순**.

`808.3가12ㄴ` → `808.3가125ㄴ` → `808.3가2ㄴ` → `808.3가55ㄴ`.

저자 숫자 125를 정수 125로 비교하지 않습니다. 0.125와 0.55를 비교하는 원리이며, 첫 자리부터 같으면 다음 자리를 계속 비교합니다. 특정 숫자쌍에만 적용되는 예외 처리가 아닙니다.

각 서가정리 창에는 별도 60초가 있습니다. 처음 60초는 배경시간을 멈추고, 그 후에는 창을 열어 둬도 배경시간이 흐릅니다. 하루에 10개 서가를 모두 성공적으로 정리하면 제자리 책 누락 이벤트를 방지할 수 있습니다. 성공/실패 상태는 다음 날 초기화됩니다.

## 전화

운영시간, 대출 권수(1인 5권), 출력 요금(A4 흑백 1면 50원), 행사 등의 질문이 나옵니다. 전화 답변은 게시판/운영 규정과 일치합니다.

- 처음 전화를 받으면 도서관 내 다른 문의의 제한시간이 10초 늘어납니다.
- 전화의 `잠시만요`는 15초 보류입니다. 다른 팝업을 읽고 있어도 이 시간은 지납니다. 끝나면 데스크로 자동 복귀하여 답변 창이 다시 열립니다. 같은 전화에서 보류는 한 번만 가능합니다.
- 오답에도 이용자는 “감사합니다”라고 끊습니다. 10초 후 45% 확률로 잘못된 안내에 항의하는 재통화가 예정됩니다. 재통화가 없어도 원래 오답은 다음 날 민원으로 남습니다. 같은 사건의 재통화는 민원 건수를 중복 생성하지 않습니다.
- 전화와 일반 문의 창은 첫 60초 동안 전체 시간을 멈춥니다. 60초 이상 닫지 않으면 “꼼수는 금지!” 안내와 함께 창이 닫히고 시간이 다시 흐릅니다. 아침 보고와 하루 리뷰는 근무 시간이 아니므로 제외됩니다.

## 검색대와 무인 대출반납기

검색대는 대출반납기 옆에 있는 별도 Blender 모델입니다.

- 검색대는 50초마다 40% 확률로 용지 부족 경고가 생깁니다. 작은 삐삐 효과음은 BGM보다 낮은 음량입니다. 이용자가 없으면 문의 타이머도 없습니다. 이용자가 도착하면 30초 안에 데스크에서 용지를 챙겨 검색대에 넣습니다.
- 정상 검색대 이용 시 40% 확률로 책 위치 문의가 생깁니다. “저기요!”와 30초 타이머가 뜹니다. 흔한남매, 싯다르타, 세네카, 브레인악셀, 취향 니트, 식탁 위의 염증, AI 작곡 수노, 인체 드로잉, 사피엔스, 손자병법, 정의란 무엇인가, 클로드 코드, 실무 엑셀, 임신 출산 육아 대백과의 지정 청구기호 14개 중에서 선택합니다.
- 무인 기기는 55% 확률로 오류가 생깁니다. 처리 수락 시 다른 문의에 5초를 더 드리고 해당 이용자의 타이머는 멈춥니다. 모두 데스크로 데리고 가야 합니다.

| 오류 | 데스크 처리 순서 |
|---|---|
| 대출이 안돼요 | 대출 |
| 대출이 안되는 책이래요 | 책 상태 확인 → 대출가능으로 변경 → 대출 |
| 개인정보가 만료되었대요 | 신원 확인 → 개인정보 갱신 |

신원 확인 전에 개인정보를 갱신하면 하루 리뷰의 `선임의 분노`에 “본인 확인을 하고 개인정보를 갱신해야죠!!”가 기록됩니다.

## 추천도서·민원·종료

기존 이달의 추천도서 공간도 유지됩니다. 1분 동안 비어 있으면 이용자가 다가와 묻습니다. “지금 만들고있어요, 조금만 기다려주세요”라고 약속한 뒤에도 1분 동안 한 권도 채우지 않으면 다시 항의하고 퇴실하며 국민신문고 민원을 남깁니다.

전화, 대면, 게시판, 상급자 질책, 시청 전화, 국민신문고 민원이 다음 날 도착합니다. 단순 안내 오답은 약한 민원, 책 제자리 누락은 게시판 민원입니다. 국민신문고를 받은 날이 3일 이상이면 해고됩니다. 같은 날 여러 건을 받아도 하루로 셉니다.

해고 화면은 별도 색상과 좌절한 사서 이미지를 사용합니다. 꽂은 책, 서가 정리 횟수, 응대 횟수, 접수된 민원을 기록 카드로 보여주고 `다시 시작하기`를 제공합니다.

## 직접 고치기

GitHub에서 파일을 열고 연필 버튼 → 수정 → Commit changes를 누르면 웹 플레이용 소스가 자동 배포됩니다. 제 로컬 작업 폴더에는 실시간으로 반영되지 않으므로, 다음 작업 때 최신 저장소를 확인합니다.

- `dist/service.js`: 전화 질문, 민원 도입 문구 `OPENERS`, 항의 문구 `RANTS`, 민원 규칙.
- `dist/operations.js`: 이용자 활동, 확률, 기기 및 데스크 처리 흐름.
- `dist/kdc.js`: 자연스러운 주제 문의, 행사 정보.
- `dist/shelving.js`: 배가 비교, 미니게임, 검색 도서 목록.
- `dist/game.js`: 화면과 버튼, 조작, 팝업/전화 보류.
- `dist/style.css`: 화면 디자인.

수정한 다운로드용 단일 파일까지 갱신하려면 `python scripts/package.py`를 실행하고 생성된 `dist/play.html`도 커밋하세요. 문서나 설명만 바꾸면 게임 행동은 자동 변경되지 않습니다.

## 개발 파일과 확인

`models/library.blend`는 기존 도서관·사서·카트 원본, `models/search-terminal.blend`는 추가 검색대 원본입니다. `models/build_search_and_fired.py`는 검색대와 해고 화면 이미지 생성 코드입니다. 게임이 사용하는 GLB와 이미지 파일은 `dist/assets`에 있습니다.

```sh
npm test
npm run check
python scripts/package.py
```

핵심 규칙과 모의 DOM에서 초기화·응대 메뉴·배가·종료/재시작·15초 전화 복귀를 확인했습니다. 실제 브라우저의 전체 5일 플레이와 드래그 조작은 이번 버전에서 검증하지 않았습니다. 진행 상황은 브라우저의 로컬 저장소에 보관됩니다. 새 흐름을 처음부터 확인하려면 게임 안의 `처음부터` 또는 종료 화면의 `다시 시작하기`를 누르세요.
